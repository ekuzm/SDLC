## Описание

Реализовано **«Баланс — система анализа и прогнозирования личного бюджета»**: веб-приложение на Go для ручного учёта личных финансов в BYN. PR объединяет материалы ЛР №3, обновлённую спецификацию и работающую реализацию.

**Автор:** Кузьменков Егор Валентинович, группа 450503.  
**Заказчик / участник учебной пары:** Новицкий Егор Юрьевич.

## Что сделано

- Регистрация, вход/выход, приватный бюджет каждого пользователя и настройка начального остатка.
- Доходы и расходы: создание, изменение, подтверждённое удаление, фильтры, страницы списка и итоги всей выборки.
- Категории и архив, месячные лимиты, состояния «достигнут» / «превышен».
- Регулярные платежи: короткие месяцы, просрочка, пропуск, перенос, создание фактической операции и привязка уже введённой.
- Аналитика категорий и сравнение периодов; прогноз остатка текущего месяца и расходов следующего с объяснением расчётов.
- Точные денежные расчёты, атомарное файловое хранилище, защита сеансов и форм, ограничение ошибок входа, ежедневные резервные копии.
- Docker/Compose, инструкции запуска и восстановления, автоматические тесты и GitHub Actions.
- Сохранены комплект SysML v2/UML и отчёт с новым дизайном пяти макетов; SRS обновлена до 0.5 с трассировкой всех 37 ID.

Сервер использует стандартную библиотеку Go 1.26; отдельная СУБД, Node.js и внешние API для запуска не требуются. Хранилище рассчитано на один процесс Linux/macOS и локальную файловую систему.

## Замечания Новицкого Е. Ю. и исправления

В [документе рецензирования](https://github.com/ekuzm/SDLC/blob/lab3-srs/docs/customer-review.md) подготовлен **проект формулировок для проверки Новицким Егором Юрьевичем**. Согласие на участие сообщено автором; придуманные формулировки не выданы за уже полученный или подтверждённый отзыв.

1. **Неполная история прогноза.** Используются только полные завершённые месяцы; при отсутствии полного месяца числовой прогноз не показывается. На экране указаны границы истории, число месяцев, дни и исходные суммы. Проверки F03, F13, F14.
2. **Повторный учёт регулярного платежа.** Исполнение и связь сохраняются атомарно; повторное или параллельное подтверждение не создаёт второй расход. Удаление связанной операции возвращает платёж в ожидаемые. Проверки F07, F08, F15, 12 параллельных запросов и браузерный повтор POST.

Исправления выполнены в коде. Существующие ID REQ-FUNC-005, 007, 013–018 и REQ-REL-001 сохранены; новые требования ради переоформления не добавлялись.

```sh
go run ./cmd/balance
# Открыть http://127.0.0.1:8080, зарегистрироваться и настроить бюджет.
# Альтернатива:
docker compose up --build -d
# Проверка:
make check
```

Начать просмотр с [README](https://github.com/ekuzm/SDLC/blob/lab3-srs/README.md), [описания реализации](https://github.com/ekuzm/SDLC/blob/lab3-srs/docs/implementation.md) и [SRS](https://github.com/ekuzm/SDLC/blob/lab3-srs/srs/srs.md). Финансовая логика — `internal/balance/model.go`, транзакции — `store.go`, HTTP/защита — `server.go` и `auth.go`.

Особое внимание: точное округление, связь «платёж–операция», изменение расписания без переписывания истории, изоляция пользователей и поведение при ошибке сохранения. Документ DOCX фиксирует этап требований; реализация и фактические снимки экранов представлены отдельно.
